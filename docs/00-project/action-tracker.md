## 4b-4. Full codebase read against Security Review Framework (2026-08-20) — ratings + Level 0 slices

Read `rating.go`/`ratings_postgres.go`/`ratings.sql` (previously unreviewed beyond the migration) and the remaining Level 0 pieces (`LinkIdentity`, email signup/login, gateway routes, the onboarding entry screen) in full.

**Notably good, worth naming**: Claude Code's own self-review caught a real Confidentiality gap in `ListRatableParticipants` before I ever looked at it — `ListRatable`'s query alone doesn't check the viewer is a participant, which would let any authenticated user enumerate any meetup's participant list by guessing a `meetup_id`; the explicit `IsParticipant` check in the service method (documented inline, citing [Security Review Framework](../03-architecture/security-review-framework.md) by name) is what actually closes it. All three [ADR-015](../04-decisions/adr-015-post-meetup-star-ratings.md) error-code refinements (Forbidden vs. Conflict, self-rating → `ErrInvalidInput` at both the app and DB-constraint layers) are correctly implemented. `LinkIdentity`'s cross-account LinkedIn collision correctly maps the unique-violation to `ErrConflict`. The onboarding entry screen's Apple/LinkedIn buttons share one `GradientButton` construction specifically so Apple is equal in size/weight to LinkedIn "by construction rather than eyeballing" — a direct, well-documented answer to Guideline 4.8's placement requirement.

- [ ] **New finding**: `LoginWithPassword` (`service.go`) has a timing side-channel that undercuts its own stated intent — `user.PasswordHash == "" || !verifyPassword(...)` short-circuits, so a federated-only account (no password set) returns near-instantly while a real wrong-password attempt pays the full argon2id computation cost first. Same *message* either way (correctly enumeration-safe on that axis), but not the same *timing* — a patient attacker could in principle distinguish "this email has no password" from "wrong password" by measuring response time. Low severity, cheap fix: always run `verifyPassword` against a constant dummy hash when `PasswordHash` is empty, so timing is uniform regardless of path.
- [ ] **Could not run automated checks**: no Go or Flutter toolchain available in this review environment (no sudo, no package-repo network access) — `go build`/`go vet`/`go test` and `flutter analyze`/`flutter test`/`dart format` were not actually executed this pass, only read statically. Should be run for real wherever Claude Code has toolchain access before this is considered fully verified.
